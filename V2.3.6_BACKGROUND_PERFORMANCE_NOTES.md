# PixMind v2.3.6 — Background & Performance

Built on the merged current main supplied as `SmartStudio-main (7).zip`.

## Goals
- Keep Face v3 recognition quality/thresholds unchanged.
- Allow Face Lab to continue after leaving the People screen.
- Add optional persistent Android background face indexing in small slices.
- Prevent heavy local AI pipelines from competing for CPU at the same time.
- Reduce UI jank during Face, Content AI and Visual embedding work.
- Make the Search-by-Image picker browse the complete photo library progressively.

## Changes

### Face indexing
- Added app-wide `FaceIndexService` independent of PeopleScreen lifecycle.
- Manual `20 next` / `all remaining` runs continue when navigating away from People.
- Existing SQLite `face_scans` resume behavior is preserved.
- Added optional Background People indexing using WorkManager slices of 4 photos.
- Background face work respects battery-not-low, storage-not-low and thermal checks.
- MobileFaceNet inference now uses `IsolateInterpreter` so inference does not block Flutter's UI isolate.
- Face model, alignment, thresholds, clustering and quality filters are unchanged.

### Heavy AI coordination
- Added a SQLite-backed `ai_work_lease`.
- Content AI, Face and Visual embedding tasks acquire the same heavy-AI lease.
- Background tasks yield/reschedule when another heavy task is active.
- Foreground tasks wait briefly rather than running two heavy pipelines concurrently.

### Content AI performance
- Named-color extraction from the 640px thumbnail now runs through `compute()`.
- Foreground content indexing yields 12ms between photos; background keeps a gentler 90ms pause.
- `Index all` label is now `Index all content` to clarify that Face v3 remains separate.

### Visual search performance
- EfficientNet preprocessing (decode/resize/tensor preparation) runs through `compute()`.
- Encoder and projection inference use `IsolateInterpreter`.
- Visual indexing participates in the same heavy-AI coordinator.
- Search-by-Image picker is now paginated (80 photos at a time) instead of being limited to the latest 120.

## Intentionally unchanged
- MobileFaceNet model and Face v3 thresholds.
- YOLO model and object-detection thresholds.
- Current OCR stack (ML Kit English + Tesseract Arabic).
- Scene model.
- Federated search behavior.
- Light ObjectBox gallery analysis (pHash/color/quality).
- FastAPI semantic search protocol and voice input.

## Recommended test order
1. `flutter --no-version-check pub get`
2. `flutter --no-version-check analyze`
3. `flutter --no-version-check build apk --release`
4. Face Lab: start 20, leave People screen, use another tab, return and verify progress continued.
5. Enable Background People indexing, exit the app normally, wait for Android scheduling, reopen and inspect Face progress/albums.
6. Run Index next 20 while scrolling/searching and compare UI smoothness.
7. Start Face Lab, then start Content/Visual work and verify tasks serialize rather than hammering the device together.
8. Open Image search and scroll beyond the newest 120 photos.
